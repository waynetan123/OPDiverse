# Step 6 decision record — external-model jobs

Pre-registration for procedure step 6: the DPO rejected answers, generated by the pinned external model over the frozen non-test bank. distill-external was planned here too and is **dropped**: the pilot showed the external model refuses its requests (below). The pins are implemented in:
- `src/etl/pinned.py` (the "External-model jobs (step 6)" section);
- `src/generators/teacher/` (requests, the near-miss rules, the build and the reports).

**They must be committed before the full external run**, so the rules are verifiably fixed before any full output exists. `generators.external` refuses to run on a dirty tree. "User" marks a decision the experiment owner made; "default" marks one proposed in planning and accepted with the plan.

## What this step does and does not cover

- **DPO.** One rejected answer per non-test item (11,598): a near miss one unit of error from gold, in the same canonical format as the gold target, which is the chosen side. Cached as `data/teacher/dpo.jsonl`, keyed by `item_id`. 9,665 items need a request; MCQ's 1,933 are rule-defined.
- **The DPO audit line** step 5 left open: near-miss constructibility.
- **Not here: distill-external.** Dropped after the pilot (see "distill-external: dropped").
- **Not here: distill-self substitution rationales.** Step 5 substituted no type (`substitution.json`: `"substituted_types": []`). distill-self stays in the primary test as the fourth arm.

## distill-external: dropped

The pilot sent the 120 trace requests (all six items of 20 CVEs) at commit `80d4515` on 2026-10-03, 02:42 UTC. **All 120 were refused**: `stop_reason: refusal`, `stop_details.category: reasoning_extraction`, 0 output tokens. The refusal explanation cites the Commercial Terms restriction on reverse engineering or duplicating model outputs. The block covered every question type, including the 322-token MCQ prompts, so it concerns what the request is for, not the item content.

Under the pinned trace rules, every item would have fallen back to the gold answer alone after its one regeneration. That makes a file identical to SFT's targets, and an arm that is SFT under another name. Rewording the request to avoid the classifier was rejected: it would evade a usage-policy control.

**Owner decision (user): distill-external is not run.** No trace requests beyond the pilot are sent, and the arm is neither trained nor evaluated. distill-self is the only distillation arm. Consequences:
- **Run count** falls from 120 to 114: 3 learning-rate sweep runs and 3 M1 seeds. With distill-self dropped it would have been 99, but step 5 kept distill-self.
- **The primary test is unchanged.** distill-external was never in it.
- **Lost: the gap between the two distill arms,** which bounded how much of a distill benefit is teacher capability rather than reasoning in the target. The write-up states that the bound is unavailable.
- **The substitution source for distill-self** would also have been unavailable, but no type was substituted.

**Alternatives considered and not taken:**
- *Have the use authorised on the account.* The plan states the owner has permission to request written-out reasoning; that permission would have to be applied to the API account by Anthropic. Applying it in a prompt is not possible. This would have kept the arm as pinned, at the cost of waiting on an outside decision.
- *An open-weights teacher run on the project's GPUs.* This keeps a distill-external row, but breaks the one-external-model pin and changes the arm's meaning, from "Claude Opus 5.5's reasoning" to "a stronger open model's reasoning".
- *Run the pinned rules anyway.* That would give a 100% gold-only file: SFT under another name, at the cost of about 23,000 refused requests.
- *Server-side `fallbacks`*, which the refusal message suggests. The project forbids them because they switch models silently, and another Claude model does not change what the terms allow.

**Why dropping it is acceptable:** distill-external was a secondary arm, reported descriptively and never in the pre-registered interaction test. Its traces were not needed for any other arm: distill-self's rationales came from the backbone at step 5, and no type was substituted. So the experiment's main question can be answered unchanged with distill-self as the only distillation arm.

The trace pins committed at `80d4515` (`TRACE_PROMPT`, `TRACE_WORDS` = 250, the 511-token cap, the validity order) are removed from the code; git history keeps them.

## Runbook

1. Commit the code, the pins, this record and the plan-document edits.
2. `PYTHONPATH=src python -m generators teacher prepare`. Already written; the rerun is byte-identical.
3. `python -m generators.external --requests data/teacher/dpo_requests.jsonl`.
4. `python -m generators teacher prepare-retry`. If it wrote `dpo_retry_requests.jsonl`, run the external runner on it; if not, skip to step 5.
5. `python -m generators teacher build` → `dpo.jsonl`, `step6_report.{json,md}`. Record the outcome below.

If a run is interrupted, or ends reporting failed requests, rerun the same command: only requests without a result are sent.
