# Step 6 decision record — external-model jobs

Pre-registration for procedure step 6: the distill-external traces and the DPO rejected answers, generated by the pinned external model over the frozen non-test bank. The pins are implemented in:
- `src/etl/pinned.py` (the "External-model jobs (step 6)" section);
- `src/generators/teacher/` (requests, trace validity, the near-miss rules, the build and the reports).

**They must be committed before the first external request**, so the rules are verifiably fixed before any output exists. `generators.external` refuses to run on a dirty tree. "User" marks a decision the experiment owner made; "default" marks one proposed in planning and accepted with the plan.

## What this step does and does not cover

- **distill-external.** One trace per non-test item (11,598): the external model's written-out reasoning, then its answer. Cached as `data/teacher/distill_external.jsonl`, keyed by `item_id`.
- **DPO.** One rejected answer per non-test item (11,598): a near miss one unit of error from gold, in the same canonical format as the gold target, which is the chosen side. Cached as `data/teacher/dpo.jsonl`, keyed by `item_id`. 9,665 items need a request; MCQ's 1,933 are rule-defined.
- **The two audit lines step 5 left open:** DPO near-miss constructibility, and how often the distill-external teacher reaches the correct answer.
- **Not here.** No distill-self substitution rationales: step 5 substituted no type (`substitution.json`: `"substituted_types": []`).

## Pins

| Pin | Value | Source |
|---|---|---|
| External model | `pinned.EXTERNAL_MODEL`, unchanged from step 4: `claude-opus-5-5`, effort `medium`, adaptive thinking, display omitted, `max_tokens` 16,000, no sampling parameters, **no server-side fallbacks** (they would switch models silently). | default |
| Transport | `python -m generators.external`, unchanged from step 4: Messages API, concurrent, checkpointed, resumable. A transport failure is re-sent; a refusal is the model's answer and is kept. `custom_id = "{job}_{item_id with : → _}_a{attempt}"`. | default |
| Trace request | `TRACE_PROMPT`: the item's own user message, unhinted, then "Before you answer, write out your reasoning step by step in plain prose, in at most 250 words (`TRACE_WORDS`). Then give the answer alone on the last line, exactly in the form the question asks for." **The training prompt stays the item's byte-identical `prompt`.** | default |
| Trace length cap | The target (reasoning, a blank line, the canonical answer) must be at most `TRACE_MAX_TOKENS − 1` = **511 tokens** under the pinned backbone tokenizer, leaving room for the stop token. That is the evaluation budget, the same one distill-self's rationales were generated under. Without it, distill-external would learn to reason past the 512-token evaluation cap and be truncated for a length setting. | user |
| Trace validity | All must hold, checked in this order; the first failure is logged:<br>1. the reply ended on its own: `stop_reason` is `end_turn` (else `refusal`, with its category, or `max_tokens`);<br>2. it has a last non-empty line (`empty`);<br>3. that line parses under the item's lenient verifier (`no_final_answer`);<br>4. the canonical form of that answer is a complete target-format answer under the strict verifier (`incomplete_answer`): CVSS with all eight metrics, `VULNERABLE: yes` with a CWE;<br>5. there is reasoning above that line (`no_reasoning`);<br>6. the target fits the cap (`too_long`). | default |
| Wrong answers | **Kept.** "Base, SFT and both distill arms never touch a verifier for data selection." The last line is replaced by the canonical form of the trace's **own** answer (`**ANSWER: B**` → `ANSWER: B`), never by gold, so no target contradicts its reasoning. Correctness is recorded for the report only. | doc |
| Trace fallback | An invalid first trace, including a refusal under `reasoning_extraction` or any other category, is requested once more with the identical request. If that also fails, the target is the gold target alone (`gold_only`), as for distill-self. Each row records `source` (`ext_a1` / `ext_a2` / `gold_only`), both attempts' reasons and refusal categories, `answer`, `correct`, `dense` and `target_tokens`. | default |
| DPO request | `DPO_PROMPT`: the gold target, the per-type rule (`DPO_RULES`), and the item's user message inside `<question>` tags. Asks for "the single most plausible wrong answer" under the rule. Structured output, one field per type (`DPO_SCHEMAS`: `cwe`, `vector` or `lines`). For exact-ID and the vulnerable find-the-error item, the rule lists gold's parents and children in view 1000 by ID and MITRE name. The model chooses on plausibility; the rules below decide admissibility. | default |
| DPO near miss, per type | **Exact-ID:** a live weakness that is a parent or child of gold. **CVSS:** gold with exactly one of the eight components changed. **Find-the-error, vulnerable:** `VULNERABLE: yes` with a parent or child of gold. **Find-the-error, patched:** `VULNERABLE: yes` with any live view-1000 weakness, gold included. **Line localisation:** gold with one line left out (only when gold has two or more lines), or one line replaced by a code line in range at least 2 away from it; F1 against gold under the pinned matcher must stay below 1. | doc + default |
| Single-line gold | Never takes the "leave one out" form: that gives `LINES: none`, a different kind of answer, not one unit of error. Affects 1,000 of the 1,933 line-localisation items. | default |
| Every rejection | Must also be strict-format under its verifier, with dense score below 1 (`not_a_near_miss` otherwise). | doc |
| DPO fallback | An invalid first proposal is requested once more with the identical request. If that also fails, the rule-built near miss is used, deterministic in `stable_rank(item_id, "dpo-rule", …)`. **Exact-ID and vulnerable find-the-error:** the lowest-ranked parent or child. **Patched find-the-error:** gold's CWE (the weakness the patch fixed). **CVSS:** the lowest-ranked of the 14 one-component changes. **Line localisation:** with two or more gold lines, drop the lowest-ranked one; with one, move it to the nearest code line at distance ≥ 2, choosing between above and below by rank. Every rule-built near miss is checked by the same validator; on the real bank all 9,665 pass. Rows record `source` (`model_a1` / `model_a2` / `rule`), the proposals, reasons and refusal categories. | default |
| MCQ | **No request.** The rejected letter is the distractor closest to gold by undirected ChildOf distance in view 1000. Ties go to the earlier position in `mcq_decisions.jsonl`'s `distractors`, which is the external model's own step-4 plausibility order. This follows the plan's table literally, and the external model's judgement still breaks ties. 2,543 of 5,799 distractors are more than 6 hops from gold, so ties are common. | user |
| Audit lines | **DPO constructibility** per type: the share valid at the first attempt without the rule, banded ≥ 50% / 10–50% / < 10% as the plan specifies, plus the rule-fallback rate. MCQ: not applicable (rule-defined). **distill-external** per type: the share of items where the teacher's answer is correct (`metric == 1` on a valid trace; gold-only rows count as not correct), banded the same way, plus the dense-score distribution, sources, reasons and target lengths. distill-external is secondary, so no band flags the primary test. | doc + default |
| Pilot | All six items of the 20 non-test CVEs with the lowest `stable_rank(cve_id, "teacher-pilot")`: 120 trace requests and 100 DPO requests. It checks the prompts, refusals and trace lengths, and prices the full run from its usage. **It decides nothing**, and its outputs never enter the final files. If it shows a prompt fault, or `too_long` above 10%, the prompt or `TRACE_WORDS` is changed, recorded here and recommitted before the full run. | default |

## Cost, before the pilot

List price is $4 / $20 per million input / output tokens, with thinking billed as output; step 4's run came to about $16 on that basis. The non-test bank is about 11.0M backbone tokens of prompt, about 90% of it find-the-error and line localisation.
- Traces: about 13–17M input and 6–23M output tokens.
- DPO: about 13–17M input and 2–15M output tokens.
- **Estimate ≈ $300–900, plus about 10% for regenerations.** The width is the unknown thinking volume on the code types. `pilot_report.md` replaces it with a figure scaled from the pilot's measured usage.

## Runbook

1. Commit the code, the pins, this record and the plan-document edits.
2. `PYTHONPATH=src python -m generators teacher prepare --pilot` (already written; the rerun is byte-identical).
3. On a machine with `pip install -r requirements-external.txt` and `.env`, at that commit:
   - `python -m generators.external --requests data/teacher/pilot/trace_requests.jsonl`
   - `python -m generators.external --requests data/teacher/pilot/dpo_requests.jsonl`
   - `python -m generators teacher pilot-report`, and record the result below.
4. `python -m generators teacher prepare`, then run the external runner on `data/teacher/trace_requests.jsonl` and `data/teacher/dpo_requests.jsonl`.
5. `python -m generators teacher prepare-retry`, then run the runner on each `*_retry_requests.jsonl` it wrote. A job with nothing to regenerate writes no file.
6. `python -m generators teacher build` → `distill_external.jsonl`, `dpo.jsonl`, `step6_report.{json,md}`. Record the outcome below.

If a run is interrupted, or ends reporting failed requests, rerun the same command: only requests without a result are sent.

## For later steps

- **Converters (step 9).** distill-external reads `distill_external.jsonl` by `item_id`, with the prompt from the bank and the `target` from the row. DPO-from-base and SFT→DPO read `dpo.jsonl` by `item_id`: `chosen` (the gold target) and `rejected`.
- **Report beside every DPO cell** the type's rule-fallback rate, and for MCQ that the negative is rule-defined. A type where most negatives came from the rule is one where the write-up says the negatives are rule-generated.
- **Report beside every distill-external cell** the gold-only rate and the teacher-correct rate per type.

## Differences from the experiment plan (now reflected in its text)

- MCQ's DPO negative is rule-defined, so the external model writes every rejected answer except MCQ's.
- distill-external traces are capped at the evaluation budget, keep wrong answers, and fall back to the gold answer after one failed regeneration.
- No distill-self substitution rationales are generated (none triggered at step 5).
- A pilot precedes the full external run.
